# Data ledger: Grill in your chat

Update this file in the same pull request whenever the hosted data flow changes. The installed tool is the comparison column on the right. A reaction is the one new call it can make, and only when you use `grill_feedback`.

Hosted mode is off unless `GRILL_HOSTED=on`. When it is on, anyone with a verified email can sign up if `GRILL_OPEN_SIGNUP=on`. Otherwise it is invite-only.

The decision, as your assistant sent it and not masked, passes through Grill's server in memory. It is never logged. A `/judge` link is the one exception: it carries the decision in its address (below). An encrypted copy is held for 15 minutes so a reaction can include it, and for 180 days only if you send that grill.

Grill only uses your decisions to give you a verdict and your later look-backs. We don't read them, share them or use them for anything else, so we can't learn what's working unless you tell us. Sending a grill after a reaction is that case.

## What does not leave

- The write-up is not logged. It is not stored, except the 15-minute reaction copy, a grill you chose to send, and, if you keep records, the first line of the decision in a draft or a record, all in the table above. The optional deepen test does not store it either. On the installed tool, asking to deepen sends it to the same judge again. In chat, that second call happens during the grill, and only the answers are kept in the layer slot above.
- A token in the query string is rejected. Grill reads a bearer token from the header only.
- The look-back funnel is four integers, `grill:metric:funnel_grills`, `grill:metric:funnel_choices`, `grill:metric:funnel_lookbacks_set`, and `grill:metric:funnel_lookbacks_done`. Each is an `INCR`. None stores a decision, a title, or a verdict. The weekly report reads them.
- The impact-email pilot adds two more integers, `grill:metric:impact_email_lookbacks` and `grill:metric:impact_email_unsubscribes`. Each is an `INCR`. A look-back counts only when the confirm page's signed-in POST records it. An unsubscribe counts once per time it is turned off. Neither stores a decision, a title, a verdict, or a cost.
- The weekly email test keeps, per Monday, sets of internal account ids under `grill:exp:weekly-email:<monday>:<part>`: who was sent, who was held out, and who came back within 7 days with a grill, a look-back or a Yes or No tap, plus an integer count of email-link opens of `/decisions`. No address, no title, no verdict, no cost. Each set expires after 180 days. The count of link opens does not expire. Deleting the account does not remove its id from these sets; they expire. Plan and rule: [docs/experiments/weekly-email.md](experiments/weekly-email.md).
- The look-back reminder in chat is a count only ("2 earlier calls are due"). It names no decision. When you say "look back" and two or more saved decisions are due, the reply lists them by title so you can say which one you mean, and an answer is saved only on the decision it names. The due list on `/decisions` is worked out from that person's records when the page loads and is not stored. A blank look-back note does not count as done.
- The impact lines, the scorecard, and the one nudge on `/decisions` are worked out from that person's own records each time the page loads. They are not stored, not logged and not counted, and only that person sees them. The Yes or No tap and the challenge kinds are stored on the record, as the row above says.
- Account pages load no analytics script. The website's visit counter is not on `/decisions`, `/account` or `/judge`.
- `/judge` is the same grill from a page, for an assistant that cannot add a connector. The decision is in the `q` query on the link, so the browser history and the host's request log can see it, and a sign-in return sends that URL to the sign-in company. The page does not send it to the judge until the person presses the button. A `q` longer than 4000 characters is dropped and not sent. Keeping records uses the same default as a grill in chat. An optional `from` names the assistant with the same client list a connector uses (`gemini`, `gemini-cli`, `antigravity`, `Google-Discovery-Engine`, `claude`, `chatgpt`, `grok`, `muse`, `meta`), and the judge request excludes that company. Anything else, including no `from`, excludes nobody. The page and the verdict then say independence was not verified.
- The website's PostHog events (off until `GRILL_POSTHOG_KEY` is set) are the same allowlisted event names and fields as Vercel's: a channel `ref` and a `records` count. No person profile, no GeoIP, a one-page-load ID. Grill's PostHog is its own organization; the build refuses a key known to belong to another company's organization.
- The judge is not picked as the host chat's model. The request is `openrouter/auto`, with no pinned model list. The author's company is excluded when Grill can tell which that is. When it cannot, nobody is excluded and the verdict says independence was not verified.
- Records you did not agree to keep are not written. A record is not written until you state a choice. If you never answer, the draft expires and no look-back is scheduled.

## Compared with the local tool

The installed tool has no account. The only thing that leaves your machine is the decision as your assistant sent it, and it goes to the model router (and to Jev, if the quality check is on). Grill does not see it unless you send that grill after a reaction. There is no look-back database.

The in-chat account adds a server in the middle, a sign-in company (Clerk), a store (Upstash), and a key Grill holds. It adds those so a chat can grill without a key on your computer, and so you can keep records if you say yes. The decision, as you stated it, passes through Grill's server in memory. It is never logged. A copy is held encrypted for 15 minutes so a reaction can include it, and for 180 days only if you send that grill. A decision record is a separate copy, and only if you choose to keep records.
