# Data ledger: Grill in your chat

Update this file in the same pull request whenever the hosted data flow changes. The installed tool is not this table. Its privacy stance is unchanged and is the comparison column on the right.

Hosted mode is off unless `GRILL_HOSTED=on`. When it is on, it is invite-only.

The decision, as you stated it, passes through Grill's server in memory. It is never logged or stored.

## What does not leave

- The write-up is not logged, and not stored. The optional deepen test does not store it either. On the installed tool, asking to deepen sends it to the same judge again. In chat, that second call happens during the grill, and only the answers are kept in the layer slot above.
- A token in the query string is rejected. Grill reads a bearer token from the header only.
- The look-back reminder in chat is a count only ("2 earlier calls are due"). It names no decision. The "Due for a look-back" list on `/decisions` is worked out from that person's records when the page loads and is not stored.
- The "Your habits" section on `/decisions` is worked out from that person's own records and drafts each time the page loads. It is not stored, not logged and not counted, and only that person sees it.
- Account pages load no analytics script. The website's visit counter is not on `/decisions`, `/account` or `/judge`.
- `/judge` is the same grill from a page, for an assistant that cannot add a connector. The decision is in the `q` query on the link, so the browser history and the host's request log can see it, and a sign-in return sends that URL to the sign-in company. The page does not send it to the judge until the person presses the button. A `q` longer than 4000 characters is dropped and not sent. Keeping records uses the same default as a grill in chat. An optional `from` names the assistant with the same client list a connector uses (`gemini`, `gemini-cli`, `antigravity`, `Google-Discovery-Engine`, `claude`, `chatgpt`, `grok`), and the judge request excludes that company. Anything else, including no `from`, excludes nobody.
- The website's PostHog events (off until `GRILL_POSTHOG_KEY` is set) are the same allowlisted event names and fields as Vercel's: a channel `ref` and a `records` count. No person profile, no GeoIP, a one-page-load ID. Grill's PostHog is its own organization; the build refuses a key known to belong to another company's organization.
- The judge is not the host chat's model. The request is `openrouter/auto`, with one company excluded, and no pinned model list.
- Records you did not agree to keep are not written. A record is not written until you state a choice. If you never answer, the draft expires and no look-back is scheduled.

## Compared with the local tool

The installed tool has no account. The only thing that leaves your machine is the decision as you stated it, and it goes to the model router (and to Jev, if the quality check is on). Grill does not see it. There is no look-back database.

The in-chat account adds a server in the middle, a sign-in company (Clerk), a store (Upstash), and a key Grill holds. It adds those so a chat can grill without a key on your computer, and so you can keep records if you say yes. It does not add a copy of the write-up. That sentence is the line that must stay true: the decision, as you stated it, passes through Grill's server in memory. It is never logged or stored.

## Miss cards (grillyour.ai/miss/)

Off unless `GRILL_MISS=1`. Separate from the account: a card is never joined to an account, a record or a usage count.

| What | Where it goes | How long | Who can delete it | Installed tool, for comparison |
|---|---|---|---|---|
| The real text you paste to check the card against | Nowhere. The box has no name, so the browser never sends it. The check runs on the page. | The life of the page | Close the page | Not used. |
| The card: seven choices, one sentence, one made-up example, and the UTC day | Upstash Redis list `grill:miss:queue`. No IP, no account, no install ID, no user agent, no time of day. | The latest 5,000 cards; older ones drop off | Grill's maintainers, on request to support@grillyour.ai | Not sent. |
| A daily count of cards | Upstash `grill:miss:count:<day>`, a number only | Two days | It expires on its own | None. |
