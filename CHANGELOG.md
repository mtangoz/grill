# Changelog

## Unreleased

- Signing in to `/decisions` and `/account` on grillyour.ai now works. Grill's pages run no Clerk script, so a production Clerk instance never handed them a session, and every return said "Sign-in didn't come back to this page." Grill now does Clerk's server-side handshake (nonce format) when the browser is signed in to Clerk or has just signed in, ties the return to the browser with a short state cookie, and keeps the person signed in to these pages for 12 hours with its own signed cookie, because Clerk's session token lasts about a minute. A form sent after that goes back to the page instead of applying. HOSTED.md, DATA-LEDGER.md and PRIVACY.md say so.
- Meta AI's custom connector can discover the sign-in server. The connector host serves Clerk's authorization-server and OpenID documents at `/.well-known/oauth-authorization-server` and `/.well-known/openid-configuration`, including the `/mcp` forms older clients request. The response is that JSON, with CORS, cached for about a minute. Protected-resource metadata is unchanged.
- The public setup page and the README show how to add Grill in Meta AI (Muse): Muse → Settings → Connectors → Add custom connector, the connector URL, and Grill's public client ID. The ID is the same for everyone and is not a secret.
- Look-back reminders for in-chat Grill. When a saved decision's look-back date comes, `/decisions` lists it under "Due for a look-back", and the next time you say what you chose, the chat adds one line counting the calls due (no titles, at most once a UTC day). An optional private calendar link, off by default and switched on from `/decisions` or `/account`, puts "Grill look-back due" on each date in your calendar app; titles only if you switch them on too. The link is shown once, stored as a hash, and stops working when you turn it off, get a new one, or delete the account. "Look back" with nothing pasted now skips calls you already looked back on, and reads the due date from the request clock. DATA-LEDGER.md, PRIVACY.md and HOSTED.md say so. Why: docs/PRD-lookback-reminders.md.
- Contribute the miss, never the decision. grillyour.ai/miss/ (off until `GRILL_MISS=1`) takes a miss card: how AI got a decision wrong, as seven choices, one sentence on what would have caught it, and a made-up example. `scripts/missCore.mjs` checks it in the browser against the person's real text, which is never sent, and blocks real names, numbers and phrases; the server checks it again and keeps it in a private queue with the UTC day only. The skill offers a card once after a miss. LEARNING.md, PRINCIPLES.md, PRIVACY.md and the data ledger say so.
- Sources a write-up cites are now flagged as not checked. The judge sees only the write-up, so it cannot open a report, a dashboard, a call or a link, and Grill's quote check only confirms the judge quoted the write-up. When the write-up names sources (links, "according to", "per the", "Source:", footnotes, named reports and decks), layer 1 ends with "Not checked: the N sources this cites. Open each and confirm it says this.", the full note lists them, and the report footer names them. The detection is local and sends nothing. The judge is told a named source is not evidence it has seen. The skill and the any-assistant prompt gain a "Check the sources" step: the assistant that can open the sources does, on the version that goes out, and marks each one exists, says it, and answers this question. "Checked for you" never covers whether a cited source exists.
- The skill's section 3 also checks the numbers before work goes out: a rate beside every count compared across groups of different size, too few events to compare, open one real instance before saying what it said, time for outcomes to arrive, a metric that measures the claim, totals recomputed from rows, verdicts quoted with their date (never from memory), coverage stated, caveats kept in summaries, and every question asked answered or marked not answered. Work is called grilled only when a judge actually answered; a self-check is a same-model check. The judge's evidence-mismatch definition names the same number errors, and a new synthetic eval case (`evidence-mismatch-outreach-copy-counts`) plants three of them.
- "What has Grill done for me?" `grill_look_back` takes `view: changes` and shows where your calls changed after a challenge: before, after, what moved it, and how it turned out so far, in your words. It gives counts only, compares rates only when each side has at least 10 calls back, and never claims a saving or what would have happened. Calls kept after a flagged challenge that then missed are listed too. In-chat Grill reads your saved records for it, and the decisions page has a "Where your calls changed" section with up to three examples. The record gains an optional `proposed_by` line (`ai` or `me`), and `decided` can end with `| after challenge N` or `| after falsifier`. Both are only in your words. Version stays 1.
- Each verdict lists challenges in two groups: "Checked for you" (bugs, facts, figures, consistency the judge could settle) and "Your call" (what turns on your own values or unwritten rules). The judge tags each challenge; untagged ones count as your call.
- A dry run that clips the payload still prints the zero-data-retention provider fields.
- Speed rule: Grill never adds a required question before the verdict on a quick or bulk grill. A forecast is an optional one-line offer after the verdict, for decisions you mark as big. The prediction question no longer blocks a grill.
- docs/PRINCIPLES.md links every promise to the code and test that enforce it, and marks promises that are prompt instructions only. `node --test scripts/principles.test.mjs` checks them. The README has a "What Grill promises" section.
- A layer that drops a clause no longer ends on a dangling dash, comma, colon, or semicolon. It keeps the previous full sentence, or closes the clause that remains.
- In-chat Grill's decisions page has a "Your habits" section, which only you see. It shows how many grills you answered with a choice, how many are still waiting for one, how often you said how sure you were, how often you changed course, and how many look-backs you have done. It also gives one suggestion. It is worked out from the records already on that page each time you open it. Nothing new is stored, and the maintainers see nothing new.
- In-chat Grill now keeps an approximate count of distinct active people per day, week and month, so the maintainers can see whether people come back. Each count is a HyperLogLog of a salted hash: it can't list who was counted and holds no email, account id or decision text. A failed count never blocks a grill. docs/DATA-LEDGER.md and docs/PRIVACY.md say so.
- A quick take stays within about 50 words by ending on a whole sentence and one grammatical question. The longer note, the options, and the full note do the same: each ends on a whole sentence, and none is cut off mid-sentence.
- The site has a Contribute page, and the header and footer link to it. CONTRIBUTING.md covers local setup, tests, and pull requests, and says the privacy promise and the different-company judge are not negotiable. GitHub has forms for an idea and a bug report.
- The privacy notes promise no ads, no selling your data, and no training on your decisions. Grill is paid for by subscriptions only.
- New pitchfork logo on the site (favicon, home-screen icon, header and link previews), the README, the Claude Desktop extension, the MCP registry entry and the in-chat connector's server info.
- In-chat Grill has two hard monthly spending caps on the free starter credit: one for the whole service (default $20) and one per person (default $1). When one is reached, the grill doesn't run and you get one plain sentence saying so; nothing is charged to you. Open sign-up is now its own switch, off by default, and an empty invite list lets nobody in. Two grills finishing at the same time no longer overwrite each other's account data, and failures now say what went wrong in plain words instead of a bare error.
- A grill opens with about 50 words: a verdict line, the sharpest point, and one cheap test. Say more, options, or your call for the next layer. A thin line gets a quick take and one question, and it can still be saved. The first-use disclosure is one line with a link to the privacy page. After a grill, the assistant does not start doing the decision unless you ask.
- The mission and vision say Grill is for stronger judgement: a different company's AI argues the other side, the person decides, and a later look-back shows how that judgement did, including when to change course. The lead line is "Hear the strongest case against your plan, then decide for yourself."
- Evidenced look-backs are reported beside the 100 real users, and never added to that count. The count is public signal issues with Event `resolved`, plus outreach replies that confirm a look-back. No new tracking.
- The verdict never becomes the decision. If you ask whether you should do it, the assistant hands the choice back and names the deciding test. Push-back does not flip the verdict without new evidence. A re-grill in the same chat shows the earlier verdict beside the new one. A copy-paste check across Claude, ChatGPT, Gemini and Grok is in docs/manual-check.md. It does not pin a model.
- The decision record can include an optional `decided` line, in your words, including a change you made because of a challenge. It is left off until you say it, and it is never invented. Version stays 1. Look-back reads it back.
- A re-grill asks one question: what changed? If nothing changed, it is a re-run: both verdicts are shown, and the new record has no `supersedes` line. If the choice changed, the new record can add `supersedes` (the earlier date and title) and `changed` (`evidence`, `goals`, `context`, or `reweighed`, then your few words). Those lines are omitted until you say the choice changed, and they are never invented. There is no superseded-by line. The earlier verdict is not sent to the judge. Look-back reads a lone record as the call it replaced, and reads `reweighed` as nothing new coming in.
- The signal form's verdict choices are solid, solid if, shaky, and doesn't hold up.
- Until 16 November 2026, a few invited people have a free key we created for them. The key is on Grill's router account, capped at $0.50 of judge spend, with no refill, zero-data-retention endpoints only and logging off. There is no account, no sign-in and no Grill server involved. Write-ups go from your computer to the router and the judge, as with your own key. Maintainers can see that key's spend (cost, model and time, never the text) and that the key is yours. The private note of which number went to whom is deleted with the keys on 16 November 2026. Totals only remain (how many keys were used, total spend), with no names. docs/PRIVACY.md says this.
- Optional anonymous usage stats, off unless you turn them on. After the first successful grill, and never again, the tool can POST one metadata ping to `https://grillyour.ai/api/ping`: a random install id, the version, the client and route, whether the grill succeeded, coarse timing, and the UTC day. Never the decision. `GRILL_PING=off` or `DO_NOT_TRACK=1` disables it. The paste route does not send it.
- Grill runs in any app that runs MCP servers: Cursor, VS Code with Copilot, Codex, Gemini CLI, Windsurf, Zed. `npx -y grillyour` starts the same server the Desktop extension ships, with no dependencies and no install script. `npx -y grillyour --set-key` saves the key once, so an app's config holds no key and can be committed. Setup for each app is in docs/ANY-APP.md. The release publishes the npm package when the `NPM_TOKEN` secret is set.
- `GRILL_AUTHOR` in an app's MCP config names the company of the assistant, for example `openai` in Codex. The judge is never from that company, even when the assistant leaves the tool's `author` field empty. The tool's description no longer assumes the assistant is Claude.
- Grill Pro setup lists Cursor, VS Code with Copilot, Codex and Gemini CLI. Each gets a config with no key in it and the judge already chosen. Cursor can run Gemini, so its safe judge is DeepSeek. Before this, a Pro key worked only in Claude Desktop and Claude Code.
- The judge also reads its key from a key file, `~/.config/grill/key` (or `$XDG_CONFIG_HOME/grill/key`, or `GRILL_KEY_FILE`), when `GRILL_API_KEY` and `OPENROUTER_API_KEY` are unset. `node scripts/judge.mjs --set-key` writes it from stdin, mode 600, so the key never sits on a command line. `--key-status` says where the key comes from without printing it. A key kept only in a project's `.env` disappears when that file is rewritten, and it can't be read back from OpenRouter or a CI secret; the key file is outside every project. Learned from a downstream team that lost theirs this way.
- The judge grades severity against the decision, not the finish of the plan. A challenge is serious when, if it is right, a rejected option looks as good or better or the chosen option must become a different plan. A fix to the plan's test, threshold, sample size or timing that can be made in place is moderate and still shows. A verdict of "weak" needs a serious challenge. The judge is told not to soften a serious flaw and not to inflate a moderate one. The paste-route judge prompt says the same. Live evals had judges from several companies and cost bands filing "serious" for detail fixes on sound decisions.
- After a finished grill, the tool can show one Grill news line, at most once a session, about an optional Pro plan (saved history and look-back reminders). It shows only when the day is within 7 days of the release date baked into that build, or on the first 3 days of a month, and not otherwise. It is on unless "Show Grill news" is switched off, or `GRILL_NEWS` is off, and it stops after 2026-11-13. The tool sends nothing and stores nothing. The paste route can show the same news once per conversation, and skips it if you declined the signal offer.
- The website replaces the "Get a starter key" button with a form to hear when Pro is ready, while accounts aren't live. Joining is double opt-in, confirmed with a button press. The confirmation link is encrypted, so the email address is not in the URL. The list is deleted 60 days after the launch email. Sign-ups are Pro interest and are not counted as users. If Resend or Upstash isn't configured, the page says sign-ups aren't open yet.
- A grill can carry an optional goal and guardrails, in the user's words. The judge checks a stated goal or guardrail and does not invent one. A trade-off the user names and accepts is not a defect. The decision record stays version 1 and adds `goal`, `guardrails` and `source_app` only when they have a value. The Grill tool does not fill in `source_app`. Look-back asks whether the goal was reached and whether the guardrails held.
- The default judge is only OpenRouter's Auto Router (`openrouter/auto`). It excludes the author's company and does not pin a fallback model. A transient failure retries that same router, with backoff and a fixed limit. If the model that answers is still the excluded company, the run errors and does not return that verdict. `JUDGE_MODEL` still overrides the chain.
